# wchup

`wchup` is a simple but modern project generator for WCH microcontrollers. It provides an alternative to the vendor-supplied MounRiver Studio environment and proprietary toolchain forks by adopting a clean, upstream LLVM/Clang toolchain, C23, CMake presets, and an ultra-lightweight bare-metal runtime.

The project is currently in its initial phase, featuring full support for the **CH32V003** (QingKe V2 RISC-V core) with LLVM `compiler-rt` builtins and a custom heapless `picolibc` deployment.

## Philosophy

Microcontroller development for WCH chips typically involves choosing between the official Eclipse-based MounRiver Studio (with customized GCC forks and non-standard interrupt behaviors) and minimal bare-metal replacements such as `ch32fun`.

`wchup` takes a different route:
- **Upstream LLVM/Clang**: Compiles firmware with standard Clang (`riscv32-unknown-elf`), LLD, and C23 (`-std=c23`). No proprietary compiler forks or non-standard language extensions are required.
- **Official Drivers, Cleaned**: Retains the official WCH peripheral driver library, but strips out vendor bloat, IDE artifacts, and Windows binaries. Peripheral drivers are selected and compiled on demand via CMake.
- **Dedicated Minimal Runtime**: Replaces newlib and vendor runtime blobs with LLVM `compiler-rt` builtins and a tailored `picolibc` build. Dynamic allocation is disabled at configuration time (`enable-malloc=false`) to eliminate heap management overhead within the 2 KB SRAM envelope.
- **Standard-Compliant Interrupts**: Disables proprietary hardware auto-stacking in the startup code so that standard Clang interrupt handlers execute reliably without stack corruption.
- **Standalone Project Generation**: Projects generated by `wchup` are completely self-contained. Toolchain files, linker scripts, driver sources, and runtime libraries are copied into each project with zero symlinks and no persistent dependencies on the `wchup` repository.

## Prerequisites

- **Python**: 3.10 or later
- **CMake**: 3.21 or later
- **Ninja**: Build generator
- **LLVM / Clang**: Clang, LLD, `llvm-ar`, and `llvm-ranlib` built with the RISC-V target backend. The toolchain must support `rv32ec_zicsr_zifencei` and the `ilp32e` ABI (verified against LLVM 23.x).
- **Runtime Libraries**: Prebuilt runtime artifacts in `llvmlib/install/` (see [Building the Runtime](#building-the-runtime)).

## Quickstart

### 1. Create a Project

Generate a new standalone project in the current working directory:

```bash
python3 /path/to/wchup/wchup.py --chip ch32v003 create my_project
```

### 2. Configure and Build

Navigate to the project directory and build using CMake presets:

```bash
cd my_project
cmake --preset release
cmake --build --preset release
```

This compiles `my_project.elf` under `build/release/` with size optimization (`-Os`), Link-Time Optimization (`-flto`), debug symbols (`-g3`), and linker memory usage reporting (`--print-memory-usage`).

To build with debug optimizations (`-Og`):

```bash
cmake --preset debug
cmake --build --preset debug
```

### 3. Debugging and Flashing

`wchup` includes wrappers for the bundled WCH-compatible OpenOCD binary:

Start the OpenOCD GDB server in the foreground:

```bash
python3 /path/to/wchup/wchup.py --chip ch32v003 openocd
```

Flash, verify, and reset the device using an ELF binary:

```bash
python3 /path/to/wchup/wchup.py --chip ch32v003 flash build/release/my_project.elf
```

## Generated Project Layout

Each generated project is fully relocated and self-contained:

```text
my_project/
├── CMakeLists.txt              # Project definition and peripheral selection
├── CMakePresets.json           # Presets for Ninja + Clang toolchain
├── cmake/
│   ├── ch32v003.cmake          # Target definitions and compiler/linker flags
│   ├── link.ld                 # Memory layout and section placement
│   ├── riscv-clang.cmake       # CMake toolchain configuration
│   └── runtime.cmake           # Imported target definitions for runtime libraries
├── include/
│   └── ch32v00x_conf.h         # Peripheral driver header includes
├── src/
│   └── main.c                  # Application entry point
└── third_party/
    ├── ch32v003/               # Cleaned WCH SDK snapshot (core, drivers, startup)
    └── runtime/
        └── rv32ec-ilp32e-nomalloc/
            ├── include/        # picolibc C standard library headers
            ├── lib/            # libc.a and libclang_rt.builtins-riscv32.a
            └── share/licenses/ # License files for compiler-rt and picolibc
```

Because all dependencies are local, the generated project directory can be relocated, committed to revision control, or distributed independently.

## Runtime Environment

`wchup` projects link with `-nostdlib` against two specific libraries:

1. **`libclang_rt.builtins-riscv32.a`**: Built from LLVM `compiler-rt`, providing software division, multiplication, and shift intrinsics for the RV32E architecture.
2. **`libc.a`**: Built from `picolibc` with the following configuration:
   - `-Denable-malloc=false`: Dynamic memory allocation routines (`malloc`, `free`, `calloc`, `realloc`) are omitted. Referencing them results in a link-time error, preventing accidental heap bloat.
   - `-Dformat-default=integer`: Compact, integer-only `printf`/`scanf` formatters. Long long and floating point I/O conversions are disabled.
   - `-Dthread-local-storage=false`: Thread-local storage and threading locks are omitted.
   - Bare-metal I/O: Standard I/O relies on application-provided static streams; picolibc CRT initialization (`picocrt`) is bypassed in favor of the curated vendor startup sequence.

## Peripheral Driver Selection

Drivers are added to the project via the `wch_add_executable` function in `CMakeLists.txt`:

```cmake
wch_add_executable(${PROJECT_NAME}
    SOURCES
        src/main.c
    PERIPHERALS
        gpio
        rcc
        usart)
```

For each peripheral listed in `PERIPHERALS`, the corresponding driver `ch32v00x_<peripheral>.c` is compiled into the target. Ensure that the corresponding header is uncommented or included in `include/ch32v00x_conf.h` (e.g., `#include <ch32v00x_usart.h>`).

Optional helper libraries, such as `debug/debug.c` (UART/SDI printf and delay routines) or `core_riscv.c`, can be added directly to the `SOURCES` list.

## Building the Runtime

Prebuilt runtime libraries for `rv32ec-ilp32e-nomalloc` are provided in `llvmlib/install/`. To rebuild them from source (requires Git, Meson, and LLVM/Clang):

1. **Fetch runtime sources**:
   Run `fetch-runtime.sh` to initialize and check out the pinned submodule revisions. For `llvm-project`, it configures a shallow, blobless clone with sparse checkout (retrieving only `compiler-rt` and the necessary CMake modules) to avoid downloading the full LLVM repository:

   ```bash
   ./fetch-runtime.sh
   ```

2. **Compile and install**:
   Run the build script for the target runtime configuration:

   ```bash
   cd llvmlib/configs/rv32ec-ilp32e-nomalloc
   ./build.sh
   ```

   This compiles LLVM `compiler-rt` builtins with CMake and `picolibc` with Meson, installing the static libraries (`libc.a`, `libclang_rt.builtins-riscv32.a`), headers, and licenses into `llvmlib/install/rv32ec-ilp32e-nomalloc/`.

## Adding Support for New Chips

To introduce support for another WCH microcontroller:
1. Add `<chip>/build` containing the chip-specific CMake modules, template, linker script, and toolchain configurations.
2. Add `<chip>/sdk` containing the curated peripheral drivers, startup code, and system initialization files.
3. If necessary, define a new runtime configuration in `llvmlib/configs/<runtime_name>` and compile its libraries.
4. Register the chip in the `CHIP_INFO` table in `wchup.py` with its resource path, OpenOCD configuration, and runtime target.
